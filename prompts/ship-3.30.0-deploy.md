## Loop

- **State:** `git status --short`, `git log --oneline -3 origin/main`,
  `gh pr list --state open`, `curl /health`, brain recall. Carry a compact state
  summary — not the previous iteration's transcript.
- **Decide:** lowest-numbered sub-goal not yet proven. One at a time.
- **Execute:** the sub-goal's commands, in order, checking each result before the
  next.
- **Verify (independent):** after Sub-goal 3, spawn a **fresh-context verifier
  subagent (frontier)** told to **refute** "3.30.0 is live and healthy". It must
  run `/health`, `/ready`, `make brain-smoke-live` and `docker images | grep
  tapps-brain-http` *itself*, confirm the image tag is `3.30.0` (not `3.29.0` or
  `latest`), and default to "not done" on any doubt. **Its verdict — not yours —
  advances the loop.**
- **On fail:** diagnose (read the actual error, inspect container state, brain
  recall) → hypothesis → fix → retry with *something changed*. ≤3 distinct
  strategies, then escalate once, then stop with a written diagnosis.
- **Record:** `tapps_memory(action="save", tier="procedural")` for any deploy
  lesson, including what failed and why.
- **Context hygiene:** prefer `docker logs --tail 40` and targeted `grep` over
  re-reading whole files; never paste a full build log into context.
- **Repeat or stop:** until Done-when. Caps: **10 iterations** AND **300k output
  tokens** — whichever binds first.

## Guardrails

- Termination: the Done-when above; caps 10 iterations AND 300k output tokens.
- **A declined decision is a clean stop, not a failure** — write the handoff and
  end. Do not retry a merge the operator declined.
- Independent verification of the deploy by a fresh-context verifier against
  ground truth (image tag + health + smoke), never self-report.
- **No fan-out.** Merging, tagging, deploying and pruning are sequential and
  coupled. Subagents verify only.
- **Never delete an unmerged branch**; never force-push; never `git reset --hard`
  on a dirty tree. Before any destructive git or docker command, print the target
  (`git branch -r --merged`, `docker ps -a --filter name=…`) in a **separate prior
  tool call**.
- **Do not chase these known-red things:** ~40 DB-dependent failures when
  `release-ready.sh` runs with a DSN (parked under TAP-5459, none in 3.30.0's
  code); `test_import_time_under_200ms` under parallel load (fixed in TAP-5675,
  but re-run it standalone before diagnosing).
- If you create test rows against the live brain while probing an endpoint,
  **delete them** and show the row count returning to its prior value.
- Scope: writes limited to `/home/wtthornton/code/tapps-brain` and the TAP /
  tapps-brain Linear project.
- Memory: recall at start, record the outcome (including failures) at each
  checkpoint.
- Engineering discipline: root-cause, never a workaround. **No
  green-by-suppression** — never skip or disable a check to make a step pass.
  Right-sized; match repo conventions; no scope creep.

## Autonomy

- Act on every reversible, in-scope step without asking: git inspection, pulling,
  building, deploying, re-running smoke, pruning **merged** branches, filing the
  Linear issue.
- **Hard-stop once, batched, in Sub-goal 0** for the four decisions — they are
  irreversible (merge, tag), operator-only (`docker/.env`), or a judgement call on
  someone else's PRs. Ask them together with a recommendation each; do not
  re-ask later.
- Everything after those answers runs to completion without further checkpoints.

## Failure handling

- Never re-run the same action on the same error. Diagnose → hypothesis → change
  something → retry.
- ≤3 distinct strategies per sub-goal; then escalate once; then stop with a
  concise written diagnosis and move to the next sub-goal.
- If the deploy leaves the stack unhealthy, **say so loudly and stop** — a broken
  live brain outranks finishing the checklist.
