## Loop

- **State:** `git status --short`, `git log --oneline -3`, brain recall for this story,
  Linear status via the `linear-read` cache. Carry forward a compact state summary —
  not the previous iteration's transcript.
- **Decide:** lowest-numbered sub-goal not yet proven. One story in flight at a time.
- **Execute:** recon subagent → write/extend tests → implement → story tests green →
  `tapps_validate_changed` (explicit paths) → full unit suite → commit → push → PR.
- **Verify (independent):** spawn a **fresh-context verifier subagent** (frontier
  tier) told to **refute** the story's proof: re-run the story's tests and
  `gh pr checks` itself, confirm the endpoint chain items 1-6 are all present, and
  default to "not done" on any doubt. Its verdict — not your own — advances the loop.
- **On fail / refuted:** diagnose (read the actual error, inspect state, brain recall)
  → hypothesis → fix → retry with *something changed*. ≤3 distinct strategies per
  story, then escalate once, then stop with a written diagnosis and move to the next
  story.
- **Record:** `brain_remember` the outcome, including what failed and why (tier
  `procedural` for a workflow lesson, `pattern` for a code convention).
- **Context hygiene:** prefer targeted `grep`/`Read(offset,limit)` over re-reading a
  4,700-line module; delegate anything that would dump >3 full files to a subagent.
- **Repeat or stop:** until Done-when. Caps: **16 iterations**, **8 hours wall clock**,
  **1.5M output tokens** — whichever binds first.

## Guardrails

- Termination: the Done-when above; caps **16 iterations** AND **8 h wall clock** AND
  a **1.5M output-token ceiling** for the run (~350k per story plus slack). Print the
  running estimate on the score line's `elapsed` field each iteration; when the
  ceiling is within one story's worth, finish the story in flight and stop with a
  handoff rather than starting another.
- Independent verification by a fresh-context verifier, against ground truth — never
  self-report.
- **No fan-out of coupled coding.** Subagents read, analyse, and verify. They do not
  edit source in parallel.
- Context hygiene: targeted grep over full re-Read; subagents absorb noisy output.
- Scope: writes are limited to `/home/wtthornton/code/tapps-brain` and the TAP/
  tapps-brain Linear project. `/home/wtthornton/code/AgentForge` is **read-only**.
- Memory: recall at story start; record the outcome (including failures) at each
  checkpoint.
- Harness compatibility: Linear writes via `linear-issue` (sequential, sentinel-gated);
  Linear list reads via `linear-read`; no `python -c`; per-edit quality nudge
  **overridden** in favour of a per-story gate.
- Discipline: root-cause, never a workaround. **No green-by-suppression** — never
  skip, xfail, or delete a failing test, and never `# type: ignore` / `# noqa` to pass
  a gate. If a test must change, the change must be justified by the behaviour change,
  as with the `_param_index` fix that replaced a brittle negative index. Right-sized;
  match repo conventions; no scope creep.

## Autonomy

- Act on every reversible, in-scope step — no "should I proceed?" checkpoints. Opening
  a PR is reversible; do it without asking.
- **Do not merge to `main`, force-push, or delete branches.** The PR is the reversible
  precursor; leave merging to the human and keep going to the next story.
- Hard-stop once (batched, with a recommendation) only for: an irreversible/outward
  step with no precursor · projected next-step cost above the ceiling · an ambiguous
  decision where a wrong guess is expensive and unrecoverable · another session's
  unrelated edits appearing in the working tree.

## Failure handling

- Never re-run the same action on the same error. Diagnose → hypothesis → change
  something → retry.
- ≤3 distinct strategies per story; then escalate once; then write a concise diagnosis
  into the story's Linear issue and move on. A blocked story must not consume the
  whole run.
