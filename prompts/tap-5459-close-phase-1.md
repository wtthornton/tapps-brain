(revoke-then-drop, guarded so a first run doesn't error on a missing role).

## Loop

- **State:** `git status` + `git log --oneline -5`; `brain_recall` prior attempts;
  `get_issue` on the current target id. Read *only* what this iteration needs.
- **Decide:** lowest-numbered sub-goal whose proof is not yet pasted.
- **Execute:** on the committed mechanism + tier above.
- **Verify (independent):** spawn a **fresh-context verifier subagent (frontier)**
  prompted to **refute** the sub-goal's proof — it must **re-run the deterministic
  check itself** (the pytest command, `gh run view`, `get_issue`) and default to "not
  done" on any doubt. **The verifier's verdict advances the loop, never the
  executor's claim.** For Sub-goal 1 specifically, the verifier must confirm the role
  was actually dropped before the run — otherwise the test proves nothing.
- **On fail:** diagnose (read the real error → inspect state → `brain_recall`) →
  hypothesis → fix → retry *with something changed*. ≤3 distinct strategies per
  sub-goal, then escalate once (stronger model / different approach), then stop with a
  concise diagnosis.
- **Record:** `brain_remember` the outcome incl. what failed and why (tier
  `procedural`; `architectural` if a design constraint surfaced).
- **Context hygiene:** prune stale file reads each iteration; prefer targeted
  `grep`/`sed -n` over re-Reading whole files; carry a compact state summary forward,
  not raw transcripts.
- **Repeat or stop:** until **Done-when** holds. Caps: **12 iterations** AND
  **~400k output tokens**.

## Failure handling

Diagnose, don't repeat. On a failed verify: read the actual error, inspect state,
`brain_recall` prior failures, form a specific hypothesis, retry *differently*. ≤3
distinct strategies per sub-goal → escalate once → stop with a diagnosis. Repeating
the same action on the same error is forbidden.
